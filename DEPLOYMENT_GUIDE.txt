================================================================================
  MoodLens Backend — Cloud Deployment Guide
  How to deploy your backend so it's always running on any system
================================================================================


OVERVIEW
--------
Right now your backend runs on localhost:5000 — it only works on YOUR machine
while the terminal is open. To make it accessible from ANY system, you need to
deploy it to a cloud server that runs 24/7.

Below are your best options ranked from easiest to hardest.


================================================================================
OPTION 1: HUGGING FACE SPACES (FREE — Recommended for you)
================================================================================

Why: Free, no credit card, supports Docker, handles large model files with
     Git LFS. You already have hf_space files from earlier.

Steps:

  1. Create a Hugging Face account at https://huggingface.co/join

  2. Create a new Space:
     - Go to https://huggingface.co/new-space
     - Name: moodlens-backend (or whatever you like)
     - SDK: Select "Docker"
     - Visibility: Public (free tier requires public)
     - Click "Create Space"

  3. Install Git LFS (needed for large model file):
     - Download from https://git-lfs.com
     - Run: git lfs install

  4. Clone your new Space locally:
     git clone https://huggingface.co/spaces/YOUR_USERNAME/moodlens-backend
     cd moodlens-backend

  5. Create these files inside the cloned repo:

     a) Dockerfile:
        - Use python:3.10-slim as base image
        - Copy your backend files (app.py, emotion_detector.py, recommender.py)
        - Copy emotion_model.h5 and preprodata.csv
        - Install requirements
        - Expose port 7860 (HF requirement)
        - Run: python app.py

     b) .gitattributes:
        Add these lines so Git LFS tracks large files:
          *.h5 filter=lfs diff=lfs merge=lfs -text
          *.csv filter=lfs diff=lfs merge=lfs -text
          *.keras filter=lfs diff=lfs merge=lfs -text

     c) requirements.txt (same as your backend one)

     d) Your Python files (app.py, emotion_detector.py, recommender.py)
        NOTE: Change the port in app.py from 5000 to 7860 for HF Spaces
        NOTE: Change file paths since model files will be in same directory

     e) Copy emotion_model.h5 and preprodata.csv into the repo

  6. Push everything:
     git add .
     git commit -m "Deploy MoodLens backend"
     git push

  7. Wait 3-5 minutes for HF to build your Docker container.
     Your backend will be live at:
       https://YOUR_USERNAME-moodlens-backend.hf.space

  8. Update your Chrome extension's popup.js and background.js:
     Change the HF_BACKEND variable to your actual URL.

Limitations:
  - Free tier has 2 vCPU, 16 GB RAM (enough for your model)
  - Space sleeps after ~48 hours of inactivity (wakes on first request,
    but takes ~30-60 seconds to cold-start)
  - To prevent sleeping: upgrade to $5/month persistent Space


================================================================================
OPTION 2: RENDER.COM (FREE TIER — Easy)
================================================================================

Why: Free tier with always-on option, easy GitHub integration, no Docker needed.

Steps:

  1. Push your backend/ folder to a GitHub repository
     (include emotion_model.h5 via Git LFS)

  2. Sign up at https://render.com (free, use GitHub login)

  3. Click "New" → "Web Service"

  4. Connect your GitHub repo

  5. Configure:
     - Name: moodlens-backend
     - Region: Pick closest to you
     - Branch: main
     - Root Directory: backend (if your repo has the full project)
     - Runtime: Python 3
     - Build Command: pip install -r requirements.txt
     - Start Command: python app.py
     - Instance Type: Free

  6. Click "Create Web Service"

  7. Your backend will be live at:
     https://moodlens-backend.onrender.com

Limitations:
  - Free tier: 512 MB RAM — this is TIGHT for TensorFlow + your 88 MB model
    You may need the $7/month "Starter" plan (1 GB RAM)
  - Free tier spins down after 15 minutes of inactivity
  - Git LFS files may need special handling on Render
  - 750 free hours/month


================================================================================
OPTION 3: RAILWAY.APP (FREE TRIAL, then ~$5/month)
================================================================================

Why: Very developer-friendly, automatic deploys from GitHub, generous resources.

Steps:

  1. Push your backend to GitHub

  2. Sign up at https://railway.app (GitHub login)

  3. Click "New Project" → "Deploy from GitHub Repo"

  4. Select your repo → Railway auto-detects Python

  5. Add environment variables if needed (e.g., YOUTUBE_API_KEY)

  6. Railway gives you a public URL automatically

  7. Update your extension with the new URL

Limitations:
  - $5 free trial credit, then pay-as-you-go (~$5/month for your usage)
  - Good resources (8 GB RAM available)


================================================================================
OPTION 4: GOOGLE CLOUD RUN (FREE TIER — Production Grade)
================================================================================

Why: Scales to zero (you only pay when someone uses it), generous free tier,
     production-grade infrastructure.

Steps:

  1. Install Google Cloud CLI: https://cloud.google.com/sdk/docs/install

  2. Create a Google Cloud project at https://console.cloud.google.com

  3. Enable Cloud Run API and Container Registry API

  4. Create a Dockerfile in your backend folder (same as HF option)

  5. Build and push the Docker image:
     gcloud builds submit --tag gcr.io/YOUR_PROJECT/moodlens-backend

  6. Deploy to Cloud Run:
     gcloud run deploy moodlens-backend \
       --image gcr.io/YOUR_PROJECT/moodlens-backend \
       --platform managed \
       --region us-central1 \
       --allow-unauthenticated \
       --memory 1Gi \
       --cpu 2

  7. You get a URL like:
     https://moodlens-backend-xxxxx-uc.a.run.app

Free Tier:
  - 2 million requests/month free
  - 360,000 GB-seconds of memory free
  - 180,000 vCPU-seconds free
  - This is MORE than enough for a student project

Limitations:
  - Requires credit card for verification (won't charge within free tier)
  - Cold starts take ~15-30 seconds (model loading)
  - More complex setup than options 1-3


================================================================================
OPTION 5: FLY.IO (FREE TIER — Good Balance)
================================================================================

Why: Free tier with always-on VMs, good for long-running servers.

Steps:

  1. Install flyctl: https://fly.io/docs/getting-started/installing-flyctl/

  2. Sign up: fly auth signup

  3. In your backend directory:
     fly launch

  4. It creates a fly.toml config file. Set:
     - App name: moodlens-backend
     - Region: closest to you
     - VM size: shared-cpu-1x, 1GB RAM

  5. Deploy:
     fly deploy

  6. Your app runs at:
     https://moodlens-backend.fly.dev

Free Tier:
  - 3 shared-cpu VMs with 256 MB RAM each (you'll need to upgrade to 1 GB)
  - $5/month for 1 GB RAM VM — very reasonable

================================================================================
AFTER DEPLOYING — WHAT TO CHANGE IN YOUR EXTENSION
================================================================================

Once your backend is live at a public URL, you need to update TWO files
in your extension/ folder:

  1. popup.js (line 10):
     Change: const HF_BACKEND = "https://YOUR_HF_USERNAME-YOUR_SPACE_NAME.hf.space";
     To:     const HF_BACKEND = "https://your-actual-deployed-url.hf.space";

  2. background.js (line 5):
     Change: const HF_BACKEND = "https://YOUR_HF_USERNAME-YOUR_SPACE_NAME.hf.space";
     To:     const HF_BACKEND = "https://your-actual-deployed-url.hf.space";

  The extension already has auto-detection logic:
    - It tries HF_BACKEND first
    - If that fails, it falls back to localhost:5000
  So your extension will work both online AND offline!


================================================================================
IMPORTANT NOTES
================================================================================

  • Your YouTube API key is embedded in recommender.py. For production,
    use environment variables instead of hardcoding it.

  • Your emotion_model.h5 is 88 MB. Most free tiers handle this fine,
    but always use Git LFS when pushing to Git repos.

  • preprodata.csv is 40 MB. Same thing — use Git LFS.

  • TensorFlow is heavy (~400 MB installed). Some platforms may take
    5-10 minutes to build the first time. Be patient.

  • For the college demo: deploy a day before, test it, and you're set.
